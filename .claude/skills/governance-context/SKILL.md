# Governance context

Published v1 · content hash 56f8ffc5 · by Anita Desai · 2026-10-13

This is the enterprise layer. It is the same for every use case and every developer. It is reference only: read the files below, no tool is needed.

## Rules

- Follow the policies, standards and guidelines in the references, at the versions named. A Block policy is a floor: nothing a project or agent skill says lowers it.
- Never override a rule here. If a task seems to conflict with one, stop and tell the Tech Lead; do not decide it yourself.
- When you rely on a rule, cite the item and its version. Never invent a clause or a version.
- The agent or project skill sits on top of this one and adds to it. If the two ever disagree, this one wins.

## Out of bounds

- Test-set content (golden or red-team cases) is not here and must not be asked for or guessed.
- Changing a policy, standard or guideline is Enterprise Governance's decision, made in the workbench, never in a repository.
